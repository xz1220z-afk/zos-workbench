# ZOS 版本备份与回读规则

> 适用于每一次新增功能、修复和正式发布。代码版本备份与用户数据备份是两件事，必须同时守住。

## 1. 每次发布必须留下四份证据

1. **Git 标签**：正式站验收通过后创建 `zos-workbench-vX.Y.Z`，它是可恢复的代码快照。
2. **功能账本**：在 `docs/feature-ledger.md` 记录需求、入口、实现文件、数据边界、测试和回滚。
3. **验收记录**：建立 `docs/zos-ceo-os-vX.Y.Z-production-acceptance.md`，记录三轮测试和生产回读证据。
4. **变更日志**：在 `CHANGELOG.md` 说明用户能看到的变化与仍未完成的边界。

只推送代码不算上线；正式站版本和关键资源完成回读后才允许打标签。

## 2. 发布前回读

开发前先回读：

- 本文件与 `docs/feature-ledger.md`；
- 当前 `CHANGELOG.md` 最近两个版本；
- 与本次页面、数据集合和安全边界有关的既有测试；
- 上一版生产验收记录与回滚标签。

开发后必须：

- 跑本功能测试和全量回归；
- 回读 `index.html`、`manifest.json`、`sw.js`、`src/app.mjs` 的同一版本号；
- 在桌面、平板、手机检查正文非空、无横向溢出、控制台无 error；
- 实际点击核心入口，不以静态截图代替交互验收；
- 确认旧路由、旧记录和既有数据集合仍可读。

可使用：

```bash
node scripts/verify-release-readback.mjs --version X.Y.Z --base https://xz1220z-afk.github.io/zos-workbench/
```

## 3. 用户数据保护

- 用户生成的任务、日历、决策、私密记录继续使用现有本机检查点、完整备份、安全合并恢复和本人私有云同步。
- 功能升级不得覆盖现有集合、清空 localStorage / IndexedDB、重放旧 tombstone 或改变本人私有 RLS。
- 任何数据迁移必须先建立检查点并回读成功；失败即停止迁移。
- 回滚代码时保留兼容数据，不做破坏性删表或批量删除。

## 4. 禁止备份

以下内容不得进入 Git 标签、验收文档或功能账本：密钥、密码、登录会话、私密聊天全文、身份证件、支付信息、Obsidian 私密正文和未经授权的飞书业务明细。

## 5. 回滚方式

1. 找到上一版已验收标签；
2. 从标签新建恢复分支，生成一个新的回滚提交，不强推、不改写历史；
3. 提升 Service Worker 缓存版本，避免旧新资源混用；
4. 重新执行全量回归、三尺寸验收和生产回读；
5. 用户数据保持原位，除非另有经过预览和明确确认的数据恢复方案。
