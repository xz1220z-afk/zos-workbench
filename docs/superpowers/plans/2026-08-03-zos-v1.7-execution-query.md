# ZOS v1.7 Execution and Query Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a four-device personal execution system with rich tasks, Pomodoro, agenda, countdowns and real calendar views, plus read-only Huahuo availability and Wanjia merchant 360 queries.

**Architecture:** Keep private owner data in the existing versioned `zos_records` pipeline and add focused domain modules for tasks, focus, countdowns, availability and merchant profiles. Extend the authenticated Feishu read contract with metadata-only fields, compose the modules in `src/app.mjs`, and render them through small view modules inside the existing PWA shell.

**Tech Stack:** Vanilla ES modules, Node `node:test`, HTML/CSS PWA, Supabase Postgres/RLS, Supabase Edge Functions, Feishu Bitable read-only API.

## Global Constraints

- No third-party runtime dependency.
- Feishu business data remains read-only and authoritative.
- Personal records remain authenticated-owner-only under Supabase RLS.
- Missing business evidence renders `未记录` or a field gap, never `未完成`.
- Private life events expose only a busy block in company contexts.
- All new code follows test-first RED/GREEN cycles.
- Mobile navigation remains exactly five primary destinations.
- Production completion requires three fresh verification rounds and page readback.

```js
export function normalizeTask(input = {}) {
  const title = String(input.title || '').trim();
  if (!title) throw new Error('task title is required');
  return {
    ...input, title, description: String(input.description || ''),
    priority: [0, 1, 2, 3].includes(Number(input.priority)) ? Number(input.priority) : 0,
    tags: uniqueStrings(input.tags), company: input.company || 'ceo',
    status: input.status || 'todo', subtasks: normalizeSubtasks(input.subtasks),
    estimateMinutes: positiveIntegerOrNull(input.estimateMinutes),
    focusMinutes: Math.max(0, Number(input.focusMinutes) || 0),
    focusCount: Math.max(0, Number(input.focusCount) || 0),
    dueAt: input.dueAt || legacyEndOfDay(input.dueDate),
  };
}
```

Add `focus_sessions` and `countdowns` to `ENTITY_TYPES`; state becomes schema `1.7` while reading v1.4 keys. Migration 007 replaces the entity type check with the full v1.7 list and preserves the existing RLS policies.
