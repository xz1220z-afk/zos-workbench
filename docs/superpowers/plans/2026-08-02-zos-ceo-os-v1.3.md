# ZOS CEO OS v1.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 v1.2.3 深色 CEO 指挥中心升级为具备决策、目标、健康、日报、四端同步、受控飞书审批、移动端行动优先和脱敏监控的 v1.3.0 生产 PWA。

**Architecture:** 保留 GitHub Pages、Supabase Auth、现有只读飞书与 Obsidian 元数据通道，新增小型原生 ES Modules、owner-scoped 数据表和两个受保护的飞书审批 Edge Functions。所有经营事实仍来自飞书 ERP/当前项目源；AI 只产出建议和待审核草稿；飞书写入必须经过预览、逐条确认、源快照核对、字段白名单、执行回读和审计。

**Tech Stack:** HTML/CSS、原生 ES Modules、Node.js 22 `node:test`、PWA Service Worker、Supabase PostgreSQL/RLS/Auth/Edge Functions、Deno TypeScript、飞书多维表格 Open API、GitHub Pages。

## Global Constraints

- 目标版本固定为 `v1.3.0`，发布日期使用实际发布日，Service Worker 缓存名固定提升为 `zos-workbench-v1.3.0`。
- 飞书 ERP、合同和当前项目源是业务实时事实；Obsidian 只上传元数据，不读取 Markdown 正文。
- 前端不得保存或接收飞书 App Secret、tenant token、service-role key、任意 app token、任意 table ID 或任意字段 patch。
- 飞书回写仅允许服务端白名单动作；逐条预览、逐条确认、十分钟过期、源记录漂移即拒绝、执行后逐字段回读。
- 目标必须由朱帅手工确认或导入已确认字段，不能由历史数据自动推断。
- 业务缺失值显示 `—`，不得用 0 或样例数字伪造事实。
- 四端继续使用一套 PWA；桌面、平板和手机共享数据契约，手机底部导航固定为：首页、决策、行动、业务、更多。
- 所有新增表必须启用 RLS、默认拒绝匿名访问、仅允许 `auth.uid() = user_id` 的 owner-scoped 操作。
- 运行事件必须脱敏，不能记录客户正文、订单正文、合同正文、Obsidian 正文、密钥或飞书原始响应。
- 每项生产代码必须先有失败测试并观察到预期失败，再写最小实现；每个任务独立提交。
- 用户现有未跟踪目录 `.superpowers/` 不属于本次变更，禁止加入提交。
