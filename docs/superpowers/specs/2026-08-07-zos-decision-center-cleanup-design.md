# ZOS CEO OS 待决策中心清理设计

日期：2026-08-07  
目标版本：v2.0.3

## 目标

把当前混在“待我决策”中的业务风险重新分成三个层级，让角标只代表朱帅本人必须拍板的事项，同时保留全部历史记录和来源证据。

## 已确认方案

1. **真正待决策**：仅保留需要 CEO 对价格、回款、资源投入、高风险或重大交付作出选择的开放事项。
2. **负责人跟进**：普通超期、状态停滞、未完成动作和一般交付任务进入跟进队列，不占用 CEO 决策角标。
3. **已解除历史**：`pending_resolution` 及已结束状态作为历史记录展示，不再进入角标、首页待决策、今日简报或优先级引擎。

## 数据边界

- 不删除任何现有决策记录，不修改飞书 ERP 原始数据。
- 不批量改变旧记录状态；分类由现有字段派生，确保旧数据和多端同步兼容。
- 原有 `open / pending_resolution / approved / rejected / deferred / resolved` 状态机保持不变。
- 数据恢复、备份、同步及 tombstone 规则不变。

## 分类规则

新增单一分类模块，所有首页、角标、简报、复盘和优先级计算统一复用。

### CEO 决策

记录必须为 `open`，并满足至少一项：

- 类别为高风险或待回款；
- 事实或建议明确涉及价格、报价、回款、收款、亏损、资源增派、重大交付、延期交付或需要 CEO 拍板；
- 未来来源明确提供 `decisionScope: "ceo"` 或 `requiresCeoDecision: true`。

### 负责人跟进

记录为 `open`，但不满足 CEO 决策规则。典型情况为超过 7 天未更新、停滞超过 14 天、存在普通未完成动作或一般交付任务。

### 已解除历史

状态为 `pending_resolution / approved / rejected / deferred / resolved` 的记录全部进入历史区，其中 `pending_resolution` 继续保留“来源风险已消失，等待人工确认解除”的事实说明。

## 界面

- 左侧角标、首页 KPI、移动端摘要只显示 CEO 决策数量。
- 决策中心顶部显示三个真实数量：需要你决定、负责人跟进、已解除历史。
- 默认先显示“需要你决定”，其后显示“负责人跟进”和“已解除历史”；历史区限制首屏数量，避免数百张重复卡片拖慢页面。
- 负责人跟进与历史卡片不展示飞书回写按钮；只有真正 CEO 决策保留“预览更新”。

## 性能

- 分类为纯函数，只遍历一次决策集合。
- 各分区进入 DOM 前设置展示上限，完整数量仍保留在统计中。
- 不新增远程请求，不增加启动同步次数。

## 验收

1. `pending_resolution` 不再计入任何“待我决策”数字。
2. 普通超期/未完成事项进入负责人跟进。
3. 回款、高风险、重大资源/交付事项仍进入 CEO 决策。
4. 现有记录数量、ID、状态和同步数据不被改写。
5. 桌面、平板、手机无横向溢出，决策中心首屏不卡顿。
6. 全量自动化测试、语法检查、差异检查通过；正式站资源版本和页面回读通过。

## 回滚

代码回滚到 v2.0.2 即恢复旧展示逻辑。由于本次不迁移、不删除、不批量更新记录，回滚不需要恢复业务数据。
