# ZOS v1.0.7 状态真实性修复设计

## 目标

让朱帅工作台的入口、版本、连接状态和登录方式与当前真实能力一致，消除会误导用户的旧文案和无入口遗留逻辑；本版本不新增业务数据源，不改动飞书、Obsidian 或 Supabase 中的业务记录。

## 当前问题

- 设置页显示旧 Coze 地址，实际正式入口是 GitHub Pages。
- 页面仍显示 v1.0.4 和“纯本地工作台”，但当前已包含 Supabase 登录与同步代码。
- 隐私页固定显示所有外部服务“未连接”，无法反映配置状态。
- 邮箱登录已改为登录链接，旧的验证码输入/验证逻辑仍残留。

## 设计

1. 统一发布信息：正式链接、版本号、更新日期和控制台文案使用一个常量。
2. 设置页的持久状态分为“未配置，仅本机”“已配置，等待登录”“已登录，可手动同步”三种可解释状态；发送失败和同步失败只显示当前操作错误，不伪造持久连接状态。
3. 设置页使用动态状态卡，Supabase 只显示“配置/登录/同步”状态；飞书、Obsidian、业务平台仍明确标记“尚未接入”。
4. 移除用户不可达的验证码输入和验证按钮，保留底层 OTP 适配器作为未来配置自定义 SMTP 后的兼容接口，但不得在当前界面暴露。
5. 所有修复通过静态回归测试覆盖，Service Worker 缓存版本升级，线上发布后验证首页、manifest、sw.js 与关键文案。

## 非目标

- 不接入飞书 ERP 实时数据。
- 不接入 Obsidian 文件读写。
- 不提高 Supabase 邮件限流或配置自定义 SMTP。
- 不自动写入、迁移、删除任何业务记录。

## 验收标准

- 正式入口只显示 GitHub Pages 地址。
- 页面显示 v1.0.7，且不再出现 v1.0.2/v1.0.4 的旧状态说明。
- 未登录时显示“已配置，等待登录”或“仅本机”，登录成功后才显示“已登录，可同步”。
- 页面不显示当前不可用的验证码输入控件。
- 现有全部自动测试通过，线上静态资源返回 HTTP 200。
