# ZOS AI 优先首页与 C 级受控执行设计规格

## 1. 目标

在现有 ZOS CEO Operating System v2.8.4 上增量增加一个统一的 AI 工作入口，让朱帅可以通过键盘或按住说话表达需求，由系统识别意图、选择正确事实源或 Agent、给出回答或执行低风险动作。现有导航、公司页面、生活首页、日历、情报中心、Agent OS、用户数据和视觉体系全部保留。

本阶段仍是四端通用 PWA。原生 iOS、后台唤醒词、持续监听和后台录音不属于本阶段。

## 2. 已确认产品原则

- 首页优先展示统一 AI 输入，而不是要求用户先判断应进入哪个页面。
- 页面继续作为核查、筛选、编辑和人工处理入口，不被 AI 首页替换。
- 键盘和语音是同一条任务链的两个输入方式。
- 语音只在用户按下或主动点击麦克风后工作；停止后立即结束收音。
- ZOS 不保存原始音频；未经用户保存或执行，不持久化临时口述文本。
- 飞书 ERP、合同、平台后台和项目源文件是实时业务事实源。
- Enterprise Brain 是知识、SOP、案例、决策依据和复盘来源，不覆盖实时经营事实。
- AI 输出必须区分事实、推断、建议、待确认和下一步。
- C 级执行仅允许低风险、可撤销动作直接执行；高风险和外部影响动作必须预览确认。

## 3. 首页信息架构

### 3.1 第一屏：AI Command Surface

工作首页第一屏改为统一 AI 操作区，包含：

1. 可多行输入的任务框；
2. “按住说话／点击麦克风”按钮；
3. 当前识别状态：待命、正在听、正在整理、已识别、不支持、权限被拒绝；
4. 可选上下文标签：自动、万嘉、花火、玲丽、生活、知识库、Agent OS；
5. 常用示例，但不预填虚假任务；
6. 最近一次结果和受控执行面板。

现有 KPI、今日 Top 3、公司经营全景、情报、日历和系统健康下移到第二屏，结构和数据不删除。

### 3.2 AI 结果卡

每次回答使用同一个结果契约：

- 我理解的任务；
- 使用的来源和数据日期；
- 事实；
- 推断；
- 建议；
- 待确认；
- 下一步；
- 执行等级与可用操作。

AI 不得把缺失数据变成 0，不得把历史快照描述成今日事实，也不得把尚未执行的动作显示为已完成。

## 4. 意图与来源路由

新增纯规则优先的意图路由层。AI 可以补充分类，但不能覆盖以下事实优先级：

| 意图 | 首选来源 | 备用来源 |
| --- | --- | --- |
| 订单、商家、任务、金额、结算、实时项目 | 飞书 ERP／现有 Supabase 只读接口 | 无权访问时返回待登录或待配置 |
| SOP、案例、方法、历史决策、复盘 | Enterprise Brain 授权索引与摘要 | 无授权摘要时只给通用分析并明确标识 |
| 日程与个人任务 | 本机／私人同步集合 | 外部日历只读结果 |
| 最新行业信息 | 情报中心的当前来源 | 公开联网来源，标注出处与日期 |
| 专业岗位任务 | Agent OS 动态身份卡、Skill、Workflow 和已确认上下文 | 没有运行能力时只生成任务草案 |

路由结果包含 `intent`、`scope`、`sourcePlan`、`agentId`、`riskLevel` 和 `requestedAction`，供界面和执行策略共同使用。

## 5. 语音输入

### 5.1 交互

- 桌面端：按住麦克风说话，松开结束；也支持点击开始、再次点击结束。
- 手机和平板：使用至少 48px 的触控目标；开始收音时显示明显但克制的动态反馈和计时。
- 识别结果先进入可编辑文本框，用户仍可修改后再提交。
- 不做“助手”持续唤醒，不在后台监听。

### 5.2 技术边界

第一阶段只使用浏览器提供的语音识别能力完成“语音转文字”，并封装为独立适配器。支持 `SpeechRecognition` 或 `webkitSpeechRecognition` 时启用；不支持、离线或权限拒绝时立即回退到键盘输入，不阻塞工作台其他功能。识别后的任务与键盘输入进入同一条任务链，回答和分析继续调用工作台现有的 OpenAI 后端，不使用浏览器内置回答代替 OpenAI。

ZOS 不记录或上传原始音频。语音识别是否由浏览器供应商在云端处理属于浏览器能力，界面须在首次使用前明确提示。后续如要改为 OpenAI 服务端转写，必须另行设计音频传输、保存时长、删除和隐私确认，不能在本阶段暗中加入。

## 6. C 级受控执行策略

### L0：只读与界面动作，直接执行

- 查询、搜索、汇总、诊断；
- 打开现有页面、切换筛选、展示商家或项目；
- 调用只读 Agent 分析；
- 生成答案和来源列表。

### L1：本地或私人同步的可撤销草案，直接执行

- 新建任务草案、收集箱草稿、提醒草稿；
- 将情报转为待办草案；
- 保存 AI 建议到现有草稿集合。

执行后必须显示结果、保存位置和“撤销”按钮。若保存失败，不得显示成功。

### L2：外部影响或高风险动作，必须确认

- 写飞书、派单、修改经营数据；
- 发送消息、发布内容；
- 创建或修改外部日历；
- 删除、批量移动、归档、改名；
- 付款、预约、合同、最终改价；
- 修改权限、凭证或自动化。

确认卡必须显示准确对象、字段变化、影响范围、测试方案和回滚方式。没有现有安全执行器时只生成草案，不伪造“已执行”。

## 7. Agent OS 集成

- AI 首页可以自动建议或由用户指定 Agent。
- Agent 从现有动态索引读取，不硬编码数量或身份。
- 调用时带入身份卡、职责边界、Skill、Workflow、知识入口、输出契约和已确认上下文。
- 每个 Agent 保留独立本地任务记录和规则快照。
- REL-001 与其他私密个人 Agent 不进入公司视图，也不上传私密上下文。
- draft 或缺少运行证据的 Agent 只生成任务草案；pilot 仅允许受限只读分析；active 且 AI 服务可用时才显示可分析。

## 8. 状态、错误与安全反馈

统一状态：

- `idle`：等待输入；
- `listening`：正在听；
- `transcribing`：正在整理；
- `routing`：正在选择来源；
- `answering`：正在分析；
- `preview_required`：等待确认；
- `executing`：正在执行允许动作；
- `completed`：真实完成；
- `failed`：失败并给出安全错误码；
- `unsupported`：当前浏览器不支持语音。

错误必须保留用户输入，允许重新提交；登录失效、来源未配置、网络中断、麦克风拒绝和 AI 未配置分别提示。禁止显示密钥、原始接口响应、私人正文或内部堆栈。

## 9. 数据保存与版本保护

- 原始音频不保存。
- 尚未提交的口述文本只保存在当前页面内存。
- 正式任务只写入现有任务、收集箱或 Agent 任务集合，不新增第二套业务数据。
- AI 活动记录仅保存脱敏后的任务摘要、来源标签、执行等级、状态和时间；不保存飞书原始行、Vault 正文或密钥。
- 发布前创建升级检查点，继续使用现有安全备份与恢复机制。
- 版本升级统一更新 `index.html`、`manifest.json`、`sw.js`、模块查询版本、版本断言和发布记录。
- v2.8.4 标签和发布提交保持不变；新版本使用独立分支与新标签。

## 10. 组件边界

- `ai-command-center.mjs`：输入契约、结果契约、会话状态和动作候选。
- `intent-router.mjs`：规则优先的意图、范围、来源和 Agent 路由。
- `controlled-execution.mjs`：L0/L1/L2 分类、预览要求和撤销契约。
- `voice-input.mjs`：浏览器语音识别适配与状态机，不包含业务路由。
- `ai-command-view.mjs`：首页输入、语音反馈、结果卡和确认卡渲染。
- `app.mjs`：复用现有 store、AI client、Agent、任务、导航和备份动作，负责事件编排。
- `dashboard-view.mjs`：在第一屏挂载 AI 操作区，原经营内容继续渲染在下方。

不大规模重构 `legacy-app.mjs`，不引入 React 或第二套框架。

## 11. 验收标准

### 功能

1. 工作首页首屏是 AI 文字／语音统一入口；旧经营模块仍可使用。
2. 语音只在用户主动操作时启动，结果可编辑，原始音频不保存。
3. 不支持语音或拒绝权限时，键盘入口始终可用。
4. 万嘉、花火、玲丽、生活、知识库、情报、日历和 Agent OS 可被正确路由。
5. 回答展示来源、事实、推断、建议、待确认和下一步。
6. L0 直接完成；L1 直接保存且可撤销；L2 必须预览确认。
7. 高风险动作没有执行器时只给草案，不能显示成功。
8. REL-001 私密边界不变。
9. 刷新、升级和离线缓存不丢失既有用户数据。

### 自动化验证

- 新模块使用 TDD，先见到失败测试再实现。
- 全量 Node 测试不得低于当前 619 个且全部通过。
- `git diff --check`、模块语法检查、PWA 缓存图验证通过。
- 禁止 `transition: all`、横向溢出和全页双重重绘回归。

### 真实界面验收

- Browser：桌面首页文字输入、语音支持状态、只读回答、L1 撤销、L2 预览。
- Chrome：登录态下 AI 与现有数据来源联动，无控制台错误。
- Computer Use：真实点击、按压反馈、焦点、抽屉和导航体验。
- 视口：桌面 1440px、平板 834px、手机 390px，正文非空且无横向溢出。
- 线上 `index.html`、`manifest.json`、`sw.js`、`src/app.mjs` 均为同一新版本且 HTTP 200，旧版本备份和标签可回滚。

## 12. 发布与回滚

开发在 `codex/ai-first-home-v2.9` 独立工作区进行。通过自动测试、三尺寸界面验收、代码复核和 GitHub Pages 线上验证后，才进入发布。

回滚方式：将 GitHub Pages 恢复到 `zos-workbench-v2.8.4` 对应提交 `29cb3ab`，并保留新版本分支、发布记录和失败证据，不删除用户数据。
