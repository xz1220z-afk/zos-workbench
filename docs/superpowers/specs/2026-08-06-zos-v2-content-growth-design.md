# ZOS CEO OS v2.0 内容增长与知识工作台设计

## 1. 目标

把 ZOS 从经营数据看板升级为朱帅在万嘉网络、花火影像、玲丽教育与个人知识管理之间使用的统一工作台，形成一条可追溯的闭环：

`收集输入 → 阅读与提炼 → 情报判断 → 选题与创作 → 人工确认 → 发布记录 → 数据复盘 → 资产沉淀`

新版不替代飞书 ERP、合同、平台后台或 Obsidian：

- 飞书 ERP、合同、平台后台继续作为订单、任务、金额、结算和内容表现的实时事实源。
- Enterprise Brain / Obsidian 继续作为长期知识、SOP、案例、决策依据与复盘的权威来源；正文默认不上云。
- ZOS 负责汇总、组织、检索、辅助判断和产生待确认草稿，不擅自外发、不绕过人工审批。

## 2. 产品决策

### 2.1 信息架构

只新增两个一级导航，避免菜单继续膨胀：

1. **内容增长**：选题、创作、内容日历、资产、数据复盘、实验、复用。
2. **Agent 工作台**：按公司和职责运行受控 Agent，保留输入、依据、产物、状态和确认记录。

现有模块升级：

- **情报中心**：每日必读、行业热点、社媒洞察、竞品观察、机会池。
- **ZOS 企业大脑**：阅读收件箱、阅读器、知识卡片、知识图谱、头脑风暴、书架。
- **复盘中心**：经营复盘、内容复盘、实验复盘与资产复用建议。
- **全局搜索**：搜索业务事实索引、项目、任务、知识元数据、情报、内容和 Agent 运行记录。

### 2.2 三家公司差异化

- **万嘉网络**：本地生活热点、商家/达人洞察、团购与直播选题、账号表现、商家案例和销售话术复用。
- **花火影像**：婚礼与商业影像趋势、作品/素材管理、内容脚本、交付案例、套餐与销售素材复用。
- **玲丽教育**：招生内容、课程内容、学员问题、活动排期、案例和课程资料复用。
- **个人**：阅读、长期主题、生活灵感、个人内容与复盘；默认与公司事实隔离。

## 3. 关键工作流

### 3.1 内容增长闭环

内容条目统一经过：`灵感 → 评估 → 计划 → 制作 → 待审核 → 已发布 → 复盘 → 可复用`。

每条内容必须保留公司、平台、负责人、来源依据、目标、状态、计划时间、实际发布时间与表现数据。一个核心创意可派生多个平台版本，但每个平台版本可独立编辑、排期与复盘。

发布动作在 v2.0 仅提供“导出/复制/标记已发布”和确认记录；没有经过平台授权与验收前，不自动发布到抖音、小红书、视频号等外部平台。

### 3.2 阅读与知识卡片

支持保存文章、视频、PDF、书籍、课程和手动笔记的元数据。阅读器采用三栏：来源列表、正文/摘要区、标注与 Agent 区。

用户可把高亮转为：知识卡片、选题、任务、项目依据或待核验事实。知识卡片保留原始来源与引用位置；没有原文授权或正文数据时只保存摘要/元数据，不伪造全文。

### 3.3 情报与社媒洞察

情报中心按“今日必读、行业、公司、平台、置信度、价值评分”组织。社媒洞察记录平台、账号/竞品、话题、用户问题、情绪、机会、证据链接和采集时间。

情报可一键转选题、知识卡片或任务。平台 API 未连接时显示“待接入”并支持手工/CSV 导入，不展示模拟实时数据。

### 3.4 Agent 工作台

Agent 分为 CEO、万嘉运营、花火导演/销售、玲丽招生/课程、知识研究和内容复盘六类。一次运行包含：目标、公司、输入引用、允许动作、产物摘要、状态、错误与人工确认。

Agent 默认只生成草稿或建议；写飞书、改业务事实、发布内容、发送消息、删除或归档均进入审批队列。

### 3.5 内容数据与资产复利

内容分析区展示发布量、完播/互动、线索、成交、投入、单条产出与趋势；没有真实数据则明确显示缺口。实验区比较封面、标题、开头、时长、发布时间等变量。资产复利区把表现良好的内容转为案例、SOP、培训材料、销售话术或系列选题候选，仍需人工确认后进入长期知识库。

## 4. 页面与交互

### 4.1 内容增长页

- 顶部：本周产出、待审核、已发布、有效线索、可复用资产。
- 主区：看板/列表/日历三种视图，支持公司、平台、负责人、状态筛选。
- 创作抽屉：核心观点、证据、目标受众、平台版本、脚本、素材、审核项。
- 侧区：推荐选题、待复盘内容、复用候选。

### 4.2 Agent 工作台

- Agent 卡片显示职责、允许动作、最近运行与健康状态。
- 运行面板支持选择公司、目标和输入引用，明确展示“会做什么/不会做什么”。
- 运行历史可过滤、查看依据、复制产物、转任务或提交审批。

### 4.3 企业大脑升级

- 阅读收件箱：待读、稍后、精选、已归档。
- 阅读器：可调宽度的阅读区与标注侧栏，支持键盘快捷操作和手机底部操作条。
- 知识卡片：来源、原文片段、我的理解、可行动项、关联项目/公司。
- 头脑风暴：卡片画布和结构化大纲双视图；手机端默认大纲视图。
- 书架：阅读进度、最近打开、标注数和复习队列。

## 5. 数据模型与同步

新增集合：

- `content_items`：内容主记录及平台变体。
- `knowledge_cards`：来源明确的知识卡片。
- `reading_items`：待读与阅读进度元数据。
- `agent_runs`：受控 Agent 运行记录。
- `social_insights`：社媒与竞品洞察。
- `content_assets`：素材、授权范围和使用记录。
- `brainstorms`：头脑风暴节点与入选方向。
- `content_experiments`：实验与真实结果。
- `compound_candidates`：案例/SOP/培训/话术等复用候选。

新增集合沿用现有本地优先状态仓库、版本、软删除、冲突处理、重试队列与安全备份。为避免发布被数据库直连网络或迁移窗口阻塞，云同步使用兼容命名空间：逻辑集合映射到现有受约束实体类型，私有载荷保留逻辑类型并在回读时还原；因此无需放宽生产约束或改变 owner-only RLS。进入云端的只包含当前用户的结构化业务状态和经过清洗的元数据；登录会话、密钥、Obsidian 正文和未授权私人内容不得上传。

## 6. 视觉系统

沿用深色 CEO 指挥中心，结合 Linear 的低干扰层级与 Readwise/Heptabase 的阅读、卡片和知识关联模式：

- 深海军蓝/石墨背景，香槟金只用于一级操作和关键指标。
- 8px 网格；主要卡片半径 10px，功能控件 6px，减少大圆角和无意义渐变。
- 桌面采用 12 栏密度布局；平板 8 栏；手机改为单列、底部快捷操作和可折叠筛选。
- 字号下限 12px，正文 14–16px，触控目标至少 44px。
- 骨架屏、渐进加载、按路由延迟初始化，首屏不等待远端业务数据。
- 状态使用文字 + 图标 + 颜色三重编码，保证弱色觉与低亮度环境可读。

## 7. 性能与可靠性

- 首屏只初始化当前路由，非当前模块按需加载。
- 大列表分页/分段渲染；搜索与筛选采用轻量索引和防抖。
- 阅读器、图谱和内容分析不阻塞工作首页。
- 远端请求设置超时、缓存、离线回退与单模块错误边界。
- 所有空状态说明真实原因并给出下一步，不用示例数字冒充业务数据。

## 8. 验收标准

### 功能验收

- P0：内容增长、阅读/知识卡片、Agent 工作台、内容分析/复盘全部可用。
- P1：社媒洞察、素材库、知识头脑风暴、阅读书架全部可用。
- P2：内容实验与内容资产复利全部可用。
- 新增记录支持创建、编辑、筛选、软删除、恢复、同步与冲突处理。
- 外发与业务事实写入均经过明确人工确认。

### 三轮验收

1. **本地自动验收**：全量回归、新增单元/集成测试、语法、模块导入、敏感字段与差异检查。
2. **本地多端验收**：桌面、平板、手机逐页检查交互、空态、加载、溢出、键盘和触控目标；控制台无致命错误。
3. **正式环境验收**：合并并推送后回读 GitHub Pages、版本化资源、Supabase 对象与正式 URL，多尺寸复验核心闭环。

任一轮失败必须修复并从该轮重新验证，不把局部通过称为上线完成。

## 9. 参考依据

- Readwise Reader：统一收集多种阅读来源、标注与笔记，强调键盘阅读与持续同步。
- Heptabase：用卡片、白板、双向链接和来源整合支撑知识理解。
- Buffer：把创意、平台差异化版本、内容日历、队列和表现复盘连接起来。
- Notion：把知识、项目、搜索与受控 Agent 放进同一工作空间。
- Linear 视觉系统：深色原生、克制边框、单一强调色、清晰信息密度与键盘优先。

## 10. 回滚

- 所有新增功能通过新路由和新增集合接入，不删除旧集合或旧页面。
- 发布前建立独立分支与版本标签。
- 如正式站异常，可回退到 v1.11.0 静态版本；新增本地集合和云端表保持兼容，不做破坏性删除。
