# ZOS 手机端 AI 办公室体验升级设计规格

## 1. 结论与范围

本次采用已确认的组合方案：

- **B 的整体结构：CEO 行动驾驶舱**；
- **A 的中央语音按钮：键盘与主动语音双入口**；
- **C 的 Agent 分层入口：组织 → 部门 → Agent**。

升级基于现有 ZOS CEO Operating System 与 v2.9.0 的 AI 优先首页继续增量开发，不新建第二套工作台，不重做左侧导航，不迁移或覆盖现有用户数据、公司数据、日历、情报、知识索引和 Agent 任务记录。

本次范围为已选择的 **B 级手机端优化**：覆盖手机端高频路径，包括工作首页、AI 入口、Agent OS、任务、日历、情报和“更多”导航；公司深层报表继续保持现有功能，只补充移动端可达性和阅读层级，不在本次重构桌面信息架构。

## 2. 现状审计

### 2.1 已存在并继续复用

- 四端通用 PWA、深色视觉体系和现有页面路由；
- 手机底部五个主入口及安全区适配；
- AI Command Surface、主动麦克风输入、文字输入和 C 级受控执行；
- Agent OS 动态身份卡、任务草案、独立规则快照和历史任务；
- 任务、日历、情报、万嘉、花火、玲丽、生活、知识库等现有模块；
- 本机优先保存、Supabase 私有同步、版本备份与恢复机制；
- 44px 以上触控目标、底部抽屉、焦点样式和 reduced-motion 基础。

### 2.2 当前体验问题

1. 桌面卡片在手机上多数只是纵向堆叠，首屏决策层级不够明确；
2. AI 与 Agent 是核心能力，但入口仍容易被页面和卡片淹没；
3. “更多”承载过多二级入口，扫描和单手操作成本较高；
4. Agent 卡片可读，但组织、部门、Agent 的关系缺少移动端渐进展开；
5. 页面切换、加载、成功、失败和长任务的触感反馈不完全一致；
6. 大列表和复杂卡片在小屏上信息密度过高，缺少摘要—展开—处理的三级结构；
7. 部分刷新仍可能让用户误以为整页重新加载，需要统一局部骨架与状态保留。

## 3. 手机端信息架构

### 3.1 底部导航

底部固定五个主入口：

1. **今日**：CEO 行动驾驶舱；
2. **日历**：默认月视图和今日安排；
3. **语音**：中央悬浮主按钮；
4. **Agent**：组织 → 部门 → Agent；
5. **更多**：公司、知识、情报、设置等低频入口。

中央语音按钮是唯一高强调主操作。它不替换页面导航，也不持续监听；点击或按住后才申请麦克风权限。键盘入口始终可用。

### 3.2 今日首页

首页按四层组织：

1. **一句动态经营摘要**：基于当前事实生成，不使用固定口号；
2. **CEO 状态条**：Agent 数量、执行中、已完成、异常任务，只展示真实状态；
3. **今日 Top 3**：最多三项，聚焦“现在应处理什么”；
4. **可折叠业务摘要**：公司经营、日历、情报、系统健康按优先级展示。

手机首屏不显示完整桌面报表。每张摘要卡提供“查看全部”进入原页面，避免复制第二套功能。

### 3.3 Agent 入口

Agent 页面使用三级渐进结构：

- 第一级：万嘉网络、花火影像、个人中心等组织；
- 第二级：组织内部门及状态摘要；
- 第三级：Agent 卡片、详情和派任务入口。

用户进入后默认看到最近使用和异常 Agent，其余按组织展开。每个 Agent 保留自己的身份、职责、能力、知识入口、模型、状态、独立规则、上下文摘要和历史任务。

## 4. 中央语音与任务链

### 4.1 交互

- 单击麦克风：开始/结束一次主动录音；
- 按住麦克风：按住说话，松开结束；
- 上滑取消或点取消：丢弃本次临时文本；
- 识别结果进入可编辑输入框，用户可修改后提交；
- 不保存原始音频，不做持续监听和后台唤醒。

### 4.2 路由

语音与键盘共用现有 AI 任务链：

1. 识别意图与组织范围；
2. 选择实时事实源、Enterprise Brain 或 Agent；
3. 生成只读回答、任务草案或精确变更预览；
4. 按 L0/L1/L2 风险等级执行；
5. 保存脱敏任务摘要与真实结果。

### 4.3 受控执行

- L0 查询、搜索、导航和只读诊断可直接运行；
- L1 本机任务、收集箱和提醒草案可保存并撤销；
- L2 飞书写入、外发、发布、外部日历、删除、付款、合同和权限修改必须展示对象、字段、影响、测试与回滚，并等待确认；
- 没有安全执行器时只能生成草案，不能显示“已完成”。

## 5. 触感与视觉规则

### 5.1 Apple 风格但不复制系统外观

- 使用现有深色品牌色，增加克制的玻璃层次、材质分层和柔和高光；
- 主按钮、普通按钮、危险按钮保持明确层级；
- 只在 `transform`、`opacity` 和必要颜色属性上做短动效；
- 禁止 `transition: all`、大面积持续模糊和高成本背景动画；
- 支持 `prefers-reduced-motion`。

### 5.2 统一反馈状态

每个操作统一使用：

- 按下：轻微缩放与亮度变化；
- 处理中：按钮内进度或局部骨架，不清空整页；
- 成功：短暂状态确认和可撤销入口；
- 失败：保留输入与页面位置，给出可重试动作；
- 页面切换：保持导航壳稳定，仅内容区局部过渡；
- 长列表：使用分页、分段或按需渲染，禁止一次渲染全部历史记录。

## 6. 各高频页面的移动端增量

### 6.1 任务

- 顶部只保留今日、逾期和我创建的快捷筛选；
- 任务详情使用底部抽屉；
- 创建任务默认带入当前组织和 Agent 上下文；
- 执行日志折叠展示，结果和异常优先。

### 6.2 日历

- 默认月视图；
- 点击日期打开当日底部抽屉；
- 长按任务进入改期或删除预览；
- 移动端不依赖桌面拖拽；
- 重要日期与情感提醒只显示摘要，不公开私人正文。

### 6.3 情报

- 最新、未读、公司和主题筛选收进可展开筛选条；
- 卡片首屏只显示标题、来源、日期、评分和一句影响；
- “问这条情报”打开底部问答抽屉，继续使用 OpenAI 与授权知识索引；
- 标记已读、生成任务草案必须有即时反馈。

### 6.4 更多

- 按“公司经营、知识与 AI、个人与系统”三组展示；
- 支持最近使用和固定入口；
- 不移除任何旧路由；
- 二级页面打开后，当前入口在更多面板中保持可见和高亮。

## 7. 性能与数据安全

- 首屏只构建首页所需模型，其他页面按需加载；
- 页面内操作只刷新当前区域，不重新渲染隐藏页面；
- AI、Agent、情报和公司数据使用独立加载状态，单一来源失败不阻塞整个首页；
- PWA 更新必须原子化更新入口、模块版本、Manifest 和 Service Worker；
- 发布前创建版本标签和功能账本记录；
- 不改变现有用户数据结构，必要的新 UI 偏好仅保存最小本地状态；
- 不上传原始音频、Vault 正文、飞书原始行、密钥或私人关系正文。

## 8. 验收标准

### 8.1 功能

1. 手机底部导航为“今日、日历、语音、Agent、更多”，旧路由全部可达；
2. 中央语音与文字进入同一任务链，拒绝麦克风后文字仍可用；
3. 首页真实展示 Agent 数量、执行中、完成和异常任务，不写死数字；
4. Agent 可按组织、部门、Agent 展开，并能带入独立规则和上下文创建任务；
5. L0/L1/L2 安全边界不变；
6. 日历默认月视图，任务可打开、改期和删除预览；
7. 情报搜索、追问、已读和任务草案均有可见反馈；
8. 页面切换不闪两次，不丢滚动位置和输入内容；
9. 既有工作台、公司页面、知识库和用户数据不受影响。

### 8.2 三轮验收

1. **功能轮**：专项测试、全量自动化、语法、PWA 模块图和数据耐久性；
2. **体验轮**：390px iPhone、412px Android、834px 平板、1440px 桌面，验证触控、抽屉、键盘、语音、空状态和无横向溢出；
3. **线上轮**：正式站资源版本一致、HTTP 200、控制台 error=0、首次加载和二次缓存加载均正常。

发布前不得只凭截图宣称完成；必须保留测试结果、线上版本、回滚标签和未完成边界。

## 9. 回滚

- 以当前正式版本和标签作为发布前检查点；
- 新版本使用独立提交和标签，不覆盖既有备份；
- 若线上验证失败，恢复上一个已验收标签并提升缓存世代重新发布；
- 回滚仅针对代码和静态资源，不删除、不回滚用户数据、Agent 记录、日历、任务或公司经营数据。
