# ZOS CEO OS v1.4 产品设计规格

**日期**：2026-08-02  
**状态**：朱帅已确认进入连续制作、三轮验收与生产发布  
**目标版本**：v1.4.0  
**生产载体**：GitHub Pages PWA + Supabase + 飞书开放平台 + Obsidian 只读元数据

## 1. 产品定位

ZOS v1.4 是朱帅管理万嘉网络、花火影像、玲丽教育与个人生活的 CEO Operating System。它不是把三张报表拼在一起，而是把“事实 → 异常 → 决策 → 行动 → 复盘 → 知识沉淀”放进一套四端通用的工作流。

实时业务事实来自飞书 ERP、合同、当前项目与 Supabase 缓存；长期方法、SOP、案例与决策依据来自 Enterprise Brain；个人生活默认仅保存在本人私有空间。系统必须区分事实、AI 建议、草稿和待确认项，不得用示例数值冒充业务数据。

## 2. 已确认方案

采用“CEO 总控塔 + 三家公司经营舱 + 独立 Life OS + 共享行动系统”的深色方案：

- 桌面：高密度 CEO 指挥中心，优先显示今天必须处理的事情；
- 平板：经营复盘、会议与项目检查；
- 手机：五个主入口，优先完成决策、跟进、快速记录和日程确认；
- 四端共享同一数据契约、账号与离线壳。

## 3. 信息架构

### 3.1 双首页

1. **工作首页**：今日 Top 3、待我决策、三家公司关键异常、待回款/待交付、今日行业情报、日历冲突、数据健康、CEO 简报。
2. **生活首页**：健康与精力、家庭关系、学习成长、个人财务、旅行兴趣、生活待办和本周复盘。生活详情不向公司页面泄露，只向工作日历共享“忙碌时段”。

### 3.2 三家公司经营舱

- **万嘉网络**：商家/合同/项目、GMV/核销、内容/直播/达人、履约、回款、结算与利润。
- **花火影像**：线索/订单/合同/定金、档期/资源、拍摄/剪辑/交付、回款、成本与毛利。
- **玲丽教育**：线索/招生、学员/合同/收款、校区/教室/排课、考勤/课消、教师与合规。当前数据未接齐时必须标记“结构已建立，事实源待接入”。

## 4. 情报中心

首页只展示 3–5 条“今日必看”，完整内容进入独立情报中心。每条情报必须包含：

- 标题、来源链接、发布时间、抓取时间；
- 可信度、价值评分、标签；
- 相关公司：万嘉 / 花火 / 玲丽 / CEO；
- 事实摘要、影响判断、建议动作；
- 状态：候选、已读、转行动、已忽略、待沉淀；
- 来源与更新时间。

情报流转为：飞书人工候选池 → 用户点击“刷新私有情报” → 受保护 Edge Function 只读拉取 → Supabase 私有摘要缓存 → 前端展示 → 人工审核 → 转决策/任务/项目 → 可选进入 Enterprise Brain。系统不得自动写知识库、外发消息或启用外部网站采集定时器；飞书同步是单向人工拉取，目标表只能由服务端环境配置。

## 5. 日历中心

- 支持日、周、月三种视图；
- 聚合本地任务、三家公司项目节点、回款/交付日期与个人忙碌时段；
- 颜色区分万嘉、花火、玲丽、个人；
- 检测时间冲突、截止日重叠、关键节点无负责人；
- 生活事件在工作视图仅显示“个人安排”，不展示标题和备注；
- 日历项的真实来源、更新时间和可写边界始终可见。

统一事件最小模型为 `id/title/startAt/endAt/allDay/company/source/privacy/owner/sourceUpdatedAt`。本人创建的日历、情报与生活项使用 Supabase `zos_records` owner-scoped RLS 跨端同步；当前产品是单用户 CEO OS，不向公司成员共享。工作页面仅消费已脱敏的生活事件视图，生活详情只在本人 Life OS 展示。

## 6. CEO 工作闭环

1. 首页识别今日 Top 3 与异常；
2. 异常进入待我决策；
3. 决策可转为任务、项目动作或飞书更新提案；
4. 飞书更新必须“预览 → 单条确认 → 服务端白名单写入 → 回读验证 → 审计”；
5. 每日简报进入收集箱待审；
6. 周/月复盘沉淀结论，只有确认后的长期价值内容才进入 Enterprise Brain。

## 7. 数据与隐私边界

- 业务事实源优先级：当前飞书 ERP/合同/项目 > Supabase 已验证缓存 > Enterprise Brain 历史知识 > AI 推断。
- 任何缺失数据均显示 `—` 或“待接入”，不得回填假值。
- 每张业务卡显示来源、更新时间、新鲜度与完整度。
- 浏览器不保存飞书 Secret、tenant token 或 service-role key。
- 情报、日历、生活与搜索数据均按 Supabase 用户 RLS 隔离。
- 关系中心只读聚合三家公司已加载的客户/商家事实，不维护第二套客户主数据。
- 全局搜索只检索当前设备已加载的数据，并明确标注业务事实、知识元数据、情报、本人行动或个人私有；离线时降级为本地缓存检索。
- 对外发送、正式飞书写入、知识库正式入库仍保留人工确认。

## 8. 四端体验

- 桌面：完整侧栏、全局搜索、经营全景与多列布局。
- 平板：两列布局、会议复盘、手指友好的筛选与审批。
- 手机：底部五项：首页、决策、行动、日历、更多；业务、情报、生活与设置从“更多”进入。
- PWA：离线壳、安装、安全区、44px 触控、恢复前台与联网后自动同步。

## 9. 上线验收

### 第一轮：功能与真值

- 全量自动化测试通过；
- 无示例 KPI 冒充事实；
- 数据来源、时间、完整度与权限状态可见；
- 情报、日历、生活与三家公司页面具备加载/空/陈旧/失败状态。
- 断网仍可打开离线壳与最近缓存；离线新增项恢复联网后进入自动同步；旧 Service Worker 缓存会在激活时清理。

### 第二轮：四端与交互

- 1280px、768px、390px 三档实际浏览器截图检查；
- 导航、搜索、筛选、工作/生活切换、日历视图、情报状态操作可用；
- 无横向溢出，触控目标、焦点与安全区通过。

### 第三轮：生产端到端

- 数据库迁移、Edge Function 与 GitHub Pages 均部署；
- 线上 PWA、Service Worker、清单、静态资源回读正确；
- 已登录真实会话验证业务只读、情报私有缓存与跨端同步；
- 回滚点、部署版本和生产证据落盘。
