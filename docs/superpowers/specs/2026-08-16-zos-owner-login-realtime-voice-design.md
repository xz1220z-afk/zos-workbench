# ZOS 单一业主登录、四端实时同步与 ChatGPT 双模式语音设计规格

**状态：** 已确认设计  
**日期：** 2026-08-16  
**目标版本：** ZOS CEO Operating System v2.11.0（实施时以发布账本的下一可用版本为准）  
**现有基线：** v2.10.0、单工作台、四端 PWA、Supabase 私有同步、C 级受控执行  

## 1. 结论

本次在现有 ZOS 工作台上增量完成四项能力，不新建第二个工作台，不改变现有导航、业务页面、Agent 身份、知识入口和用户数据结构：

1. 四端统一的独立登录页，未完成身份验证前不启动工作台；
2. 单一业主账号授权，封住“任意已登录账号可读全局经营数据或调用飞书审批”的权限漏洞；
3. 任务、收集箱、日历、Agent 任务等用户数据的四端实时同步，以及经营事实源的受控自动刷新；
4. ChatGPT 快速语音与实时双向语音两种模式，共用现有 Agent、知识入口与 C 级受控执行边界。

首期仅允许朱帅的一个 Supabase 账号访问，Mac、Windows、iPhone、Android 使用同一账号。员工、客户和多角色权限不在本次范围内，但服务端授权模块需保留将来扩展角色策略的接口。

## 2. 现状审计

### 2.1 已有能力

- `src/supabase-auth.mjs` 已支持邮箱密码、邮件链接、OTP、刷新会话；
- `src/app/browser-runtime.mjs` 已从 `zos_supabase_session` 恢复会话并创建业务、AI、日历和同步运行时；
- `src/app/sync-controller.mjs` 已支持本机变更防抖上传、联网恢复、页面重新可见时同步、冲突与墓碑合并；
- 设置页已有 Supabase 项目、邮箱、密码和同步入口；
- AI Command Surface 已有键盘与主动麦克风入口，Agent 已有独立规则、知识入口和上下文摘要；
- PWA 已覆盖桌面、平板、iPhone 和 Android。

### 2.2 当前问题

1. 登录入口藏在设置页，静态工作台外壳会在鉴权前先显示；
2. 应用启动后才判断会话，未形成真正的登录门禁；
3. 邮件登录请求允许自动创建用户；
4. 敏感 Edge Function 多数只执行“已登录”校验，没有执行“唯一业主”校验；
5. 任意合法 Supabase 用户理论上可读取全局飞书经营数据；
6. 任意合法 Supabase 用户理论上可创建并执行其自己的飞书变更审批；
7. 当前同步主要由本机变更、联网与页面可见事件触发，其他设备的修改不能主动唤醒本设备；
8. 现有语音偏向浏览器转写，尚未形成完整的 OpenAI 音频输入、音频输出和实时对话链路。

## 3. 产品范围与硬约束

### 3.1 本次完成

- 独立登录页与鉴权状态机；
- 记住邮箱、系统密码管理器自动填充、会话恢复与退出；
- 单一业主服务端白名单；

- 用户数据实时推送、权威回读、离线补传和冲突提示；
- 快速语音：录音/转写、可编辑文字、ChatGPT 回答、OpenAI 语音朗读；
- 实时语音：WebRTC 双向语音、打断、静音、字幕和显式结束；
- 四端适配、三轮验收、版本备份、发布和回滚。

### 3.2 本次不完成

- 不保存明文密码；
- 不开放注册；
- 不增加员工、客户或多角色权限；
- 不做持续后台监听和唤醒词；
- 不把飞书轮询结果描述为实时事实；
- 不自动执行飞书写入、发布、删除、付款、合同或权限变更；

- 不在本阶段实现 Passkey、Face ID 或 Touch ID 登录，但保留后续入口。

## 4. 四端独立登录体验

### 4.1 启动状态机

应用只有五种入口状态：

1. `checking`：显示 ZOS 安全验证页，不创建业务运行时；
2. `signed_out`：显示邮箱密码登录页；
3. `authenticating`：登录按钮局部加载，保留输入内容；
4. `authorized`：业主身份确认后才动态加载现有工作台模块；
5. `blocked`：会话合法但不是业主，清除会话并显示无权访问。

未进入 `authorized` 前：

- 现有侧栏、移动底栏、页面内容和经营数据均不可见；
- 不初始化自动刷新、实时同步、Agent 巡检、天气、日历或 AI；
- 不请求飞书、知识库和业务数据；
- 登录页本身不得包含任何业务摘要或私密数据。

### 4.2 登录页

登录页包含：

- ZOS 品牌、简短欢迎语和当前网络提示；
- 邮箱输入框，使用 `autocomplete="username"`；
- 密码输入框，使用 `autocomplete="current-password"`；
- 显示/隐藏密码；
- “记住邮箱”复选框；
- “登录工作台”主按钮；
- “发送邮件登录链接”备用入口；
- 登录失败、无权限、网络不可用和会话失效的明确提示。

不显示注册按钮，不要求用户配置 Supabase URL 或 Publishable Key。现有固定项目配置继续由应用内安全配置提供；设置页只保留连接状态、同步状态、退出和设备管理。

### 4.3 记住账号与密码

- 工作台只在用户勾选时保存邮箱；
- 密码只存在于当前登录请求的内存中，请求完成后立即清空输入；
- 密码保存交给 Apple 密码/iCloud 钥匙串或浏览器密码管理器；
- 应用不得把密码写入 LocalStorage、IndexedDB、日志、备份、同步记录或埋点；
- 刷新令牌沿用现有会话存储，但必须通过敏感字段过滤和备份测试防止外泄。

### 4.4 会话与退出

- 有效会话启动时先刷新并执行服务端业主检查，再进入上次页面；
- 会话失效回到登录页，不删除本机工作数据；
- “退出登录”清除会话并关闭实时连接，可保留记住的邮箱；
- “移除此设备”必须二次确认，清除会话、邮箱偏好和本机用户数据，不影响云端；
- 离线时不得解锁工作台；即使本机保存过已验证会话，也必须联网重新完成业主核验后方可进入。
- 该规则覆盖新设备与已验证设备，避免离线页面中的本地写入入口绕过“只读”语义。

## 5. 单一业主授权与安全修复

### 5.1 服务端授权模型

在 `supabase/functions/_shared/auth.ts` 增加统一的 `requireOwnerUser`：

1. 验证 Supabase JWT；
2. 读取服务端 Secret `ZOS_OWNER_USER_ID`；
3. 比较当前 `user.id`；
4. 缺少配置时安全失败；
5. 匿名请求返回 401，非业主用户返回 403；
6. 日志只记录安全错误码，不记录 Token、邮箱或业务正文。

### 5.2 必须接入业主授权的路径

- `zos-business-data` 的所有全局经营数据分支；
- `zos-feishu-approval-preview`；
- `zos-feishu-approval-execute`；
- 新增的身份检查、快速语音和 Realtime 会话接口；
- 其他扫描发现会跨用户读取全局飞书、知识或企业数据的函数。

用户私有表仍同时依赖 `user_id` 和 RLS。前端是否隐藏按钮不能替代服务端授权。

### 5.3 漏洞修复不变量

- 业主原有只读经营数据能力保持；
- 业主原有审批预览、快照、过期、单次执行和回读控制保持；
- 非业主即使拥有合法 Supabase 会话，也不能读取全局数据或执行审批；
- 邮件登录设置为不自动创建用户；
- OpenAI、飞书和 service role 密钥只存在于服务端 Secret。

## 6. 四端实时同步

### 6.1 用户数据实时链路

任务、收集箱、项目、日历、Agent 任务、草稿和允许同步的偏好继续使用现有 `zos_records` 与合并规则：

1. 本机写入立即保存；
2. 在线时由现有同步控制器上传；
3. Supabase Realtime 只向当前业主的私有订阅发送变更信号；
4. 其他设备收到信号后不直接信任事件负载，而是执行一次防抖的授权拉取；
5. 通过现有 `applyRemoteSnapshot`、版本、墓碑和冲突规则合并；
6. 合并后只刷新当前可见区域。

运行时依赖必须固定版本并随 PWA 本地发布，不使用运行时 CDN。Realtime 表必须启用 RLS 和受控 Publication；登录退出、页面销毁或账号失效时必须取消订阅。

### 6.2 同设备多标签页

使用 `BroadcastChannel` 发送最小“发生变化”信号；其他标签页仍从本机权威 Store 回读。浏览器不支持时退回现有 `storage`/可见性同步机制。

### 6.3 离线与冲突

- 离线写入进入现有待上传队列；
- 恢复网络后自动重放；
- 删除继续使用墓碑，不能被旧设备复活；
- 无法安全合并时显示“存在冲突，需确认”，不静默覆盖；
- 实时连接失败时自动降级到现有联网、可见性和本机变更触发同步。

### 6.4 经营数据

- 万嘉、花火和玲丽仍以飞书、SQLite 历史仓和当前平台事实源为准；
- 业务批次、摘要快照或健康状态变化可唤醒页面重新读取；
- 没有新批次时不得改变业务数据日期；
- 页面显示“数据日期”“最后同步时间”“来源状态”和“可信状态”；
- 历史快照、周期累计和今日值继续严格区分；
- 来源失败时保留上次成功数据并明确标注“部分来源未更新”。

### 6.5 用户可见状态

统一显示：

- `已实时连接`；
- `正在同步`；
- `离线，待同步`；
- `存在冲突，需确认`；
- `部分来源未更新`。

## 7. ChatGPT 双模式语音

### 7.1 快速语音

适用于短查询、记录、派任务和情报追问：

1. 点击或按住麦克风开始；
2. 松开或再次点击结束；
3. 生成可编辑文字；
4. 用户确认后进入现有 ChatGPT/Agent 任务链；
5. 返回文字答案，并使用 OpenAI 音频输出朗读；
6. 支持暂停、继续、停止和关闭自动朗读；
7. 原始音频只用于本次转写，不保存、不进入备份和同步。

优先复用现有浏览器语音识别；不支持或识别失败时，使用受业主授权的服务端音频转写降级。文字回答继续通过现有 OpenAI Responses/AI Assistant 服务，音频输出通过服务端生成并以短期流返回。

### 7.2 实时语音

适用于连续讨论、复盘、经营分析和头脑风暴：

- 用户必须显式点击“开始实时对话”；
- 浏览器使用 WebRTC 发送麦克风音轨并播放模型音轨；
- 支持语音活动检测、打断 AI、静音、字幕、文字补充和显式结束；
- 不持续监听、不后台唤醒；
- 页面进入后台、退出登录、网络中断、连续静默 90 秒或达到单次 15 分钟上限时关闭会话；结束前 30 秒显示可见提醒；
- WebRTC 不可用时自动降级到快速语音。

OpenAI 官方文档建议浏览器和移动设备的语音到语音场景优先使用 WebRTC，并要求标准 API Key 留在服务端；浏览器只能使用服务端创建的短期凭证或经服务端统一建立会话：

- https://developers.openai.com/api/docs/guides/realtime-webrtc

新增受业主保护的 `zos-ai-realtime-session` 函数，固定使用官方 WebRTC 统一会话接口：

1. 浏览器在用户点击后创建 WebRTC offer，并把 SDP 与 Supabase 会话发给函数；
2. 函数验证 Supabase 会话和唯一业主；
3. 函数在服务端读取 `OPENAI_API_KEY`；
4. 函数把 SDP、服务端固定的模型、声音、工具和时长配置发送到 OpenAI `/v1/realtime/calls`；
5. 函数设置不可逆的散列安全标识，并只把 OpenAI 返回的 SDP answer 交给浏览器；
6. 浏览器建立 WebRTC 音频和数据通道，标准 API Key 与短期客户端密钥均不进入前端。

Realtime 模型名称通过服务端配置，发布时验证当前账号可用性；不在前端写死模型。快速语音在 Realtime 模型不可用时仍须可用。实时对话结束后默认只保存脱敏摘要、明确任务和结果状态；完整文字记录只有在用户点击“保存本次对话”后才进入个人私有数据区，原始音频始终不保存。

### 7.3 上下文

每次语音请求只装配最小上下文：

- 当前页面和组织范围；
- 选中 Agent 的身份、职责、规则和输出格式；
- 当前任务、情报或商家对象的安全摘要；
- 授权知识入口检索出的最小相关片段；
- 当前用户允许使用的只读工具。

不整库发送 Vault，不发送飞书原始表、密钥、私人关系正文、医疗或财务敏感细节。跨万嘉、花火、玲丽和个人空间的上下文默认隔离。

### 7.4 C 级受控执行

- 查询、搜索、导航和只读分析可直接运行；
- 本机任务、草稿和提醒生成后显示结果并支持撤销；
- 飞书写入、发布、外发、删除、付款、合同和权限修改只能生成精确预览；
- 语音中的“确认”不能单独触发高风险执行；
- 高风险动作必须回到屏幕显示对象、字段、影响、测试和回滚，并由用户点击确认；
- 没有执行器时只能显示草案，不得谎报完成。

## 8. 交互与视觉

- 登录页延续 ZOS 深色品牌，使用克制玻璃层次、清晰前景对比和 44px 以上触控目标；
- 支持 iOS/Android 安全区、软键盘和密码管理器；
- 处理中只更新按钮或当前区域，不清空整页；
- 登录、同步和语音状态使用统一的按下、加载、成功、失败和重试反馈；
- 不使用 `transition: all`，支持 `prefers-reduced-motion`；
- 实时语音必须有持续可见的麦克风状态、计时、静音和结束按钮；
- 未获得麦克风权限时文字输入仍可用。

## 9. 失败与降级

| 场景 | 行为 |
|---|---|
| 无会话 | 只显示登录页 |
| 合法会话但非业主 | 403、清除会话、显示无权访问 |
| 会话刷新失败 | 保留本机数据，返回登录页 |
| 新设备离线 | 不允许进入工作台 |
| 已验证设备离线 | 返回登录页，联网后重新验证 |
| 任何离线会话 | 不解锁工作台，不执行本机或远端写入 |
| Realtime 断开 | 降级到现有事件触发同步 |
| WebRTC 不可用 | 降级到快速语音 |
| 麦克风拒绝 | 保留文字输入 |
| OpenAI 语音失败 | 保留文字回答，可重试朗读 |
| 单一业务来源失败 | 保留上次成功数据，其他模块继续工作 |

## 10. 测试与验收

### 10.1 安全轮

- 匿名访问敏感函数为 401；
- 非业主合法会话访问全局业务数据、审批、语音会话为 403；
- 业主保持原有能力；
- 缺少 `ZOS_OWNER_USER_ID` 时安全失败；
- 邮件登录不会创建新用户；
- 密码、Token、API Key 不进入存储、备份、日志或实时频道；
- 高风险语音工具调用只能生成预览，不能执行。

### 10.2 功能轮

- 四端登录、记住邮箱、密码管理器、会话恢复、退出和移除设备；
- 登录前不渲染工作台、不发业务请求；
- 四端新增、修改、删除和墓碑同步；
- 离线补传、冲突检测、Realtime 断线重连和降级；
- 快速语音转写、编辑、ChatGPT 回答和音频播放；
- 实时语音连接、打断、静音、字幕、结束和超时；
- Agent 和知识上下文隔离；
- 原有业务、日历、情报、知识和 Agent 回归。

### 10.3 体验与线上轮

- 390px iPhone、412px Android、834px 平板、1440px 桌面；
- 无横向溢出、键盘遮挡、重复闪烁或整页清空；
- 首次加载、二次缓存和 PWA 更新资源版本一致；
- 正式站 HTTP 200、控制台 error=0；
- Supabase Functions 已部署且 Secret 仅服务端可见；
- 两台真实设备交叉验证同步和会话退出；
- Realtime 模型可用性、费用上限和超时策略已回读。

## 11. 发布与回滚

1. 发布前创建代码标签、功能账本和可恢复检查点；
2. 数据库 Realtime Publication、Edge Function 和静态 PWA 分阶段部署；
3. 先验证业主账号，再验证匿名与非业主拒绝；
4. 最后发布前端登录门禁和语音入口；
5. 原子更新 `index.html`、模块查询参数、`manifest.json`、Service Worker 缓存世代和版本断言；
6. 上线三轮验收通过后才标记完成。

回滚只恢复代码、静态资源、Realtime Publication 和函数版本，不删除、不回滚用户数据。关闭 Realtime 后，现有同步控制器仍须可用；关闭实时语音后，快速语音和文字输入仍须可用。

## 12. 完成定义

只有同时满足以下条件才能宣称上线：

- 独立登录门禁在四端生效；
- 单一业主授权在服务端生效；
- 两个高风险权限漏洞有失败测试和修复验证；
- 四端实时同步、离线补传与冲突保护通过；
- 快速语音和实时语音均能调用 ChatGPT，并遵守 Agent 上下文与执行边界；
- 全量自动化、四尺寸体验和正式站验证全部通过；
- 版本备份、提交号、部署版本、回滚方式和未完成边界已记录。
