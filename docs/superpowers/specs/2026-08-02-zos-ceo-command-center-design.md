# ZOS CEO 指挥中心（深色四端版）设计规格

## 目标

将现有 ZOS 工作台升级为深色 CEO 指挥中心：让朱帅在桌面、iPad、手机浏览器和可安装 PWA 中，以同一套界面完成「看经营、定优先级、推进项目、审核风险、调用知识」五类动作。

本次是界面与信息架构升级，不改变已上线的数据写入边界。飞书 ERP 是经营事实源，Obsidian 仅提供知识库元数据索引；AI 仅创建建议或待执行队列，不自动写入任何业务系统。

## 范围

本次统一升级以下既有页面与组件：

1. 首页 / Command Center
2. 今日行动、收集箱与任务
3. 万嘉网络、花火影像、企业项目
4. ZOS 企业大脑
5. 风险与审核、隐私与数据、设置
6. 桌面侧边栏、移动底部导航、顶部全局操作区、状态与空态组件

不包含原生 iOS 或 Android 应用；四端指同一响应式 PWA 在 macOS/Windows、iPad、iPhone 和 Android 上一致可用。

## 信息架构

### 1. Command Center 首页

首页按 CEO 的决策顺序组织，而非按系统模块堆叠：

- **首屏：晨间判断。** 问候、日期、全局刷新、快速创建、系统连接状态；右侧展示固定的经营原则，不伪装成 AI 实时结论。
- **经营脉搏：** 万嘉 GMV、花火回款、进行中项目、待办 / 待审核、知识库索引和风险。每张卡均显示来源、同步状态与更新时间；缺数据时显示“等待首次同步”，不显示示例数字。
- **今日决策：** 今日任务、待审核收集箱、需要人工决定的项目或风险。无内容时给出对应的下一步操作。
- **经营全景：** 万嘉与花火的真实只读汇总、项目推进和交付 / 回款风险；点击进入对应业务页。
- **执行层：** 今日日程、最近知识、AI 指令队列、系统健康。AI 指令仍需人工入队，不自动执行。

### 2. 业务与行动页

每个页面采用相同的三级结构：

1. 页面标题 + 数据来源与状态
2. 关键指标或筛选项
3. 可行动的列表、空态和明确入口

其中：

- **今日行动：** 合并今日任务、收集箱、AI 待执行指令，按“必须处理 / 可跟进”排序。
- **万嘉网络：** 商家、动销、支付 GMV、核销 / 退款趋势与商家经营明细；仅展示 Edge Function 返回的已验证字段。
- **花火影像：** 项目、交付、收款三条事实链；项目预算、交付状态或收款字段不存在时明确显示“源表未返回”。
- **企业项目：** 本地导入或 Supabase 同步的只读项目索引，突出阶段、负责人、下一步和风险。
- **企业大脑：** 笔记元数据、收集箱草稿、知识标签和 AI 指令队列；不读取、不上传笔记正文。
- **风险与审核：** 只汇总规则识别或人工待处理项，按严重程度展示来源和处理入口；不得将推断显示为事实。

## 视觉系统

采用深色 CEO 指挥中心风格，参考用户确认的第二张图，但不复制其品牌资产。

- 深色蓝黑背景、分层深色面板、低对比边框；金色作为重点和导航强调，蓝绿作为同步 / 健康状态，橙红仅用于风险。
- 统一的卡片、标签、状态点、进度条、表格与空态。信息先后遵循“状态 → 数字 / 内容 → 来源 → 操作”。
- 图标使用现有 Emoji 或轻量文本图标，不新增第三方图标依赖。
- 每张数值卡要有来源与时间；没有可信值时显示长破折号和原因。

## 四端响应式规则

| 设备 | 布局 | 导航 | 重点 |
| --- | --- | --- | --- |
| 桌面（>= 1200px） | 12 列网格，首页可三栏 | 固定侧栏 | 全局经营与多模块并读 |
| 平板（768–1199px） | 双栏优先，卡片自动折行 | 可收起侧栏 | 今日行动与经营对照 |
| 手机（< 768px） | 单栏，关键卡优先 | 底部五项导航 | 今天、业务、项目、知识、更多 |
| PWA | 复用手机 / 平板布局 | 支持安全区与离线提示 | 可安装、可恢复本地工作状态 |

移动端不复制桌面全部密度：业务明细以摘要 + 点击展开的形式显示，避免横向表格溢出。

## 数据状态与错误处理

所有页面使用一致状态标识：

- **已同步：** 已读取到可信数据，展示更新时间与来源。
- **待同步：** 尚未完成首次导入 / 刷新，提供安全的刷新或导入入口。
- **待确认：** AI 建议、风险推断或审核项，明确说明需要人工处理。
- **读取失败：** 展示人能理解的错误原因和重试入口，不暴露凭证、令牌或内部堆栈。

业务卡不可使用缓存或样例数据伪装为实时数据；当飞书、Supabase 或 Obsidian 索引不可用时，保留页面结构并给出来源级错误提示。

## 组件边界

- `app shell`：主题、顶栏、桌面侧栏、移动底栏、页面容器。
- `status card`：来源 / 同步状态 / 更新时间 / 指标或空态。
- `action list`：任务、收集箱、待确认项；支持来源标签和安全跳转。
- `business panel`：万嘉、花火、项目的真实只读数据展示。
- `knowledge panel`：只读 Obsidian 索引与 AI 指令队列。
- `empty/error state`：统一解释缺失数据、连接失败和下一步。

现有本地任务、收集箱、项目和 AI 指令的数据模型保持不变；本次仅替换渲染与导航层。只有为测试或复用确有必要时才从 `index.html` 抽取无副作用的 UI 辅助函数，避免无关重构。

## 验收标准

1. 所有既有导航页仍可打开；桌面侧栏与移动底栏不会失效。
2. 首页不出现任何硬编码的经营示例数字；真实值、空值和异常可区分。
3. 万嘉、花火、项目、企业大脑的现有刷新 / 上传 / 筛选动作仍可工作。
4. 任务、收集箱、AI 队列仍遵循当前写入边界，AI 不自动执行或外发。
5. 375px、768px、1280px 三个宽度下不出现不可读溢出、遮挡或不可点击的主操作。
6. 现有自动化测试继续通过；新增 UI 回归测试覆盖导航、数据状态和关键空态。
7. 上线前检查静态页面语法、PWA 基线和 GitHub Pages 实际页面加载。

## 非目标

- 不创建新的飞书表、不改动飞书业务记录。
- 不更改 Supabase Edge Function 的业务映射，除非测试证明界面所需的现有字段无法安全读取；该类改动另行单独说明。
- 不把 Obsidian 正文、飞书凭证、Supabase 密钥或登录令牌放入前端。
