# ZOS CEO OS 统一经营与生活工作台设计

日期：2026-08-07  
目标版本：v2.1.0

## 目标

在不改变飞书 ERP、Obsidian 与 Supabase 权威边界的前提下，一次性补齐五个高频工作流：批量决策处理、充实生活首页、三家公司三级经营页、通用仪式提醒与私人日期元数据入口、情报筛选排序。升级只增加可逆的展示与本地操作，不删除历史、不自动写回飞书、不上传私人笔记正文。

## 总体结构

采用统一的三级信息架构：

1. **CEO 总览**：只显示指标、异常、待行动和最近更新时间。
2. **经营分析**：展示公司专属漏斗、交付、回款、档期或课消等分析模块。
3. **事实明细**：保留现有飞书只读记录、商家 360、花火档期和数据源状态。

工作首页不展示私人事项的标题或关系信息；生活首页是私人内容的唯一完整入口。

## 模块一：待决策批量工作台

- 历史记录增加复选框、选择当前页、清空选择和浮动批量操作栏。
- 批量操作提供“标记已复核”和“重新打开可恢复项”。
- `pending_resolution` 与 `deferred` 可以重新打开；`approved`、`resolved`、`rejected` 只允许标记已复核，避免改变既有决定。
- 批量执行前展示数量与动作；执行后保留 8 秒撤销入口。
- 批量动作只更新 ZOS 决策记录，不批量写飞书，不删除原始历史。
- 搜索、公司和状态筛选后，“选择当前页”只选择当前可见记录。

## 模块二：生活首页与仪式提醒

生活首页从六个空数字卡升级为四块：

1. **今天与未来 7 天**：生活任务、私人日程和即将到来的重要日子。
2. **全年仪式提醒**：内置通用节日、节气、季节关怀、家人关怀与月度生活仪式；默认只提醒，不自动创建任务。
3. **生活领域**：健康、家庭关系、学习、个人财务、旅行兴趣、生活复盘。
4. **私人日期来源**：显示“本地记录 / OBS 元数据”的连接状态与隐私说明。

通用仪式提醒按月日和提前天数生成未来提醒。用户可忽略、转成生活任务或新增为私人重要日子。

### OBS 私人日期边界

- 默认不读取、不上传私人关系档案正文。
- 只接受用户主动导入的 JSON 元数据；允许字段为 `title`、`date`、`monthDay`、`category`、`reminderDays`、`recurring`、`privacy`。
- `privacy` 强制为 `private`；不接受聊天记录、关系备注、电话、地址、财务或正文。
- 工作端只能看到“私人忙碌”或“今天有私人提醒”，不能看到标题。
- Obsidian 继续保存原件，工作台只保存可删除、可重新导入的提醒副本。

## 模块三：三家公司三级经营页

### 万嘉网络

- CEO 总览：支付 GMV、商家总数、动销商家、动销率、数据新鲜度。
- 经营分析：商家经营漏斗、异常与待跟进、万嘉相关最新情报。
- 事实明细：保留商家 360、飞书只读记录与刷新状态。

### 花火影像

- CEO 总览：合同额、已收、待收、进行中项目、待交付。
- 经营分析：回款与交付风险、项目阶段、近期档期、花火相关最新情报。
- 事实明细：保留档期查询、项目明细与飞书只读状态。

### 玲丽教育

- CEO 总览：招生线索、在读学员、实收、成本、毛利、课消。
- 经营分析：招生转化、班级/课程、课消与续费、合规与数据缺口、玲丽相关最新情报。
- 事实明细：若飞书数据未接通，显示待接入字段和连接动作，不用 0 或示例数字代替。

## 模块四：情报中心

- 默认排序改为“发布时间最新优先”，不能再以评分优先覆盖时效性。
- 支持排序：最新、评分、可信度。
- 支持筛选：公司、来源、可信度、状态、时间范围。
- 支持关键词搜索标题、事实、影响和标签。
- 顶部显示筛选结果数量，提供一键重置。
- 卡片保留查看来源、标记已读、转为行动；增加忽略入口，所有状态都基于真实记录。
- “今日必看”仍只包含最近 72 小时，但完整列表允许查看更早的缓存记录。

## 模块五：交互与视觉

- 复选框、批量操作栏、筛选器与公司模块使用统一的 44px 触控高度。
- 点击反馈使用 80ms 缩放，悬停使用 140ms 抬升，浮层使用 180–220ms 进入。
- 关键动作使用暖金色，选中状态使用低饱和蓝，不依赖颜色单独传达状态。
- 空状态必须给出下一步，不再只显示“暂无数据”。
- 桌面、平板、手机无横向溢出；手机筛选器折叠为两列或纵向。
- 所有新增动效支持 `prefers-reduced-motion`。

## 数据与安全

- 飞书 ERP 是公司经营事实源；工作台不推测缺失数字。
- Obsidian 是长期私人档案原件；仅主动导入的日期元数据进入工作台。
- Supabase 只同步当前用户的私有集合；新字段沿用现有版本、冲突、备份、恢复和 tombstone 机制。
- 批量处理、情报状态和私人提醒均先写本地，再走现有私有同步。
- 本次不执行飞书批量写入、不修改飞书表结构、不删除 OBS 文件。

## 错误处理

- 批量选择包含不支持的状态：跳过不支持项并明确报告数量，不静默改变状态。
- 批量保存失败：保留选择并提示重试，不声称全部成功。
- OBS 元数据文件字段越界或含敏感字段：拒绝导入并说明允许字段。
- 情报时间无效：降级使用抓取时间；两者都缺失时排在最后并标记“时间待核对”。
- 公司数据未接通或过期：显示来源状态和最后成功时间，不展示伪造的 0。

## 性能约束

- 决策历史继续按 6 条首屏、每次 12 条加载。
- 情报筛选和排序只处理内存中最多 100 条当前列表。
- 公司页复用已有业务缓存，不新增进入页面时的网络请求。
- 通用仪式库为静态小型数据，不加载第三方日历库。
- 页面首次可操作时间不得比 v2.0.4 基线明显变慢。

## 验收标准

1. 历史记录可多选、选择当前页、批量复核、批量重新打开可恢复项并撤销。
2. 生活首页显示未来 7 天、通用仪式提醒、领域进度和私人来源状态。
3. OBS 导入只接受白名单日期元数据，正文与敏感字段无法进入状态库。
4. 万嘉、花火、玲丽均具有 CEO 总览、经营分析、事实明细三级结构。
5. 情报默认最新优先，搜索、排序和五类筛选可组合并可重置。
6. 全量自动化测试通过；桌面 1440×900、平板 1024×768、手机 390×844 三轮验收无溢出、控制台错误为 0。
7. 正式站 `index.html`、`manifest.json`、`sw.js` 和浏览器模块全部回读为 v2.1.0 后才算上线。

## 回滚

代码可回滚至标签 `zos-workbench-v2.0.4`。新记录使用兼容字段，旧版本会忽略它们；不需要删除业务数据或恢复飞书/Obsidian。
