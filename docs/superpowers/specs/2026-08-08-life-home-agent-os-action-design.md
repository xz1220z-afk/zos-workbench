# ZOS 生活首页与 Agent OS 可调用化｜增量设计

日期：2026-08-08
状态：待朱帅复核
范围：保留现有 ZOS CEO Operating System 的导航、页面、任务、日历、Agent 索引、同步和隐私边界；仅在既有生活首页与 Agent OS 页面增量调整。

## 目标

1. 生活首页从平铺卡片改为“今天优先”的私密生活入口：先帮助朱帅回到当天节奏，再提供关系、健康、仪式与生活管理入口。
2. Agent OS 从身份卡浏览页升级为可直接下达任务的受控工作台。每个 Agent 保有独立规则、独立上下文引用与可回读任务档案。
3. 不把 Agent 草稿、试运行或局部上下文冒充成自动执行或事实源；不自动外发、写飞书、创建日历、付款或改 Vault。

## 现状与约束

- 已有 Agent OS 索引扫描器只读取 Vault 元数据。正式 GitHub Pages 无权限直接扫描 Mac 文件夹，因此首次或变更后仍由用户导入本机 JSON 索引。
- 当前真实索引含 21 个 Agent、12 个 Skill、6 个 Workflow、12 个评估、5 个日志、7 个 Runbook；状态为 18 `draft`、3 `pilot`、0 `active`、0 `deprecated`。
- 现有 `agent_runs` 与任务抽屉必须保留。`REL-001` 和私密生活信息不进入共享或公司工作区。
- 飞书 ERP、合同与原始业务系统仍是实时业务事实源；Vault 是知识、规则、方法和决策依据，不替代实时业务记录。

## 生活首页设计

### 第一层：今天

首屏只保留四类信息：天气与体感、剩余可支配时间、一个“给自己”的行动、一个关系或仪式提醒。主操作为“记录生活事项”；次操作为“查看完整日历”。没有数据的模块不占用大卡片空间。

### 第二层：本周值得记住

将“未来 7 天”“重要日子”“仪式提醒”合为单一生活节奏区。按日期排序，最多展示五项；点击进入现有日历或重要日子抽屉。仪式提醒只能生成生活事项草稿，不能自动下单、外发或建公开日历。

### 第三层：生活管理

健康与精力、学习成长、个人事务与出行、私人资料改为可展开的二级入口。只有存在待办、临期事项或用户主动展开时展示详情。现有全部生活事项保留，改为可筛选时间线：今天、本周、关系、健康、学习、事务。

## Agent OS 设计

### Agent 身份层

每张卡继续动态来自身份卡索引，显示 Agent ID、分类、状态、职责、Skill 数、最近变更和 Pilot 证据。身份层定义硬规则：允许范围、禁止动作、输出合同、允许知识入口和隐私级别；不能由一次任务覆盖。

### 专属上下文层

每个 Agent 只读取三个范围的上下文：

1. 该 Agent 身份卡声明的知识入口与 Skill/Workflow 元数据。
2. 本任务由朱帅明确选择的项目、公司事实或资料引用。
3. 该 Agent 已确认的长期上下文摘要。

上下文条目必须有来源、更新时间、适用范围、隐私级别和状态。万嘉、花火、玲丽与个人生活默认隔离；公司 Agent 不读取私密生活，`REL-001`、健康及私人事务不进入云端或共享队列。

### 直接派任务

卡片新增“派任务”。打开既有任务输入/抽屉，并预填 Agent 身份、可用 Skill、允许知识入口、固定输出格式和禁止动作。朱帅填写目标、期限、关联公司/项目和可读取资料后，任务立即保存到**本机执行队列**，状态为 `draft`。

默认流程：

`draft → analysis_requested → result_ready → context_candidate / awaiting_external_confirmation`

- 已配置并登录的 OpenAI 服务可执行只读分析，输出固定包含：事实、推断、建议、待确认、下一步、引用来源和数据缺口。
- OpenAI 未配置时，仍可创建完整任务草稿，并明确显示“AI 服务未连接”，绝不伪造回答。
- 写飞书、通知负责人、创建日历、发布内容、付款或其他外部动作只可从 `awaiting_external_confirmation` 进入，并必须显示精确变更、测试和回滚方案后由朱帅单次确认。

### 任务档案与长期上下文

- 每次任务保留本 Agent 的目标、输入引用、输出摘要、状态、审批记录、关联任务及后续动作，供该 Agent 的下一次相关任务回读。
- 任务完成后自动生成“上下文候选摘要”。候选不自动升级为长期记忆。
- 朱帅可在 Agent 详情中确认、编辑、拒绝或删除候选；确认后才进入该 Agent 的长期上下文。
- 长期上下文只保存摘要与引用，不保存私密聊天全文、账号密码、定位、未确认猜测、私人财务/医疗细节或原始正文。

### 可用性状态

Agent OS 顶部显示每个 Agent 的真实可用状态：

- `未导入索引`：只显示导入说明。
- `可起草`：身份卡已载入，可保存本机任务草稿。
- `可分析`：身份卡、登录与受控 OpenAI 服务均可用。
- `试运行`：只允许身份卡明确的 Pilot 范围。
- `待外部确认`：已有变更预览，等待朱帅确认；不是已执行。

状态不等同于 `draft/pilot/active` 身份状态，页面必须同时清晰展示两者。

## 数据模型与同步

- 复用现有 `agent_os_indexes`、`agent_runs`、任务抽屉与本机状态机制；新增的 Agent 上下文条目和私密 Agent 任务默认本机保存。
- 云端仅在既有安全模型允许时保存非私密任务的最小引用；不上传身份卡正文、原始知识正文或私密上下文。
- 每次页面打开时只读检查当前已导入索引的哈希和生成时间；本机 Agent OS 文件变更后，提示重新导入，不伪造已自动扫描。

## 错误处理与回滚

- 索引缺失、JSON 不合法、索引包含正文、OpenAI 未配置、鉴权失效或知识无授权时，保留当前任务与已导入索引，显示准确状态而不清空数据。
- 所有 Agent 长期上下文的确认、编辑、删除均有本机回读与一次撤销入口。
- 回滚只撤销新增页面和本机数据结构版本；保留既有生活事项、日历、任务、Agent 执行记录、Vault、飞书和云端数据。

## 验收标准

1. 生活首页在桌面与移动端均按“今天 → 本周 → 生活管理”呈现，空模块不制造大面积空白。
2. 21 个真实 Agent 从导入索引动态展示，分类、身份状态和可用性状态均不写死。
3. 每个 Agent 可创建带规则和专属上下文的本机任务草稿；未接 OpenAI 时可起草但不能声称完成分析。
4. 有受控 OpenAI 服务时，分析只使用该 Agent 的允许上下文并输出固定事实/推断/建议结构。
5. 每次任务自动形成上下文候选，但未经朱帅确认不会成为长期上下文。
6. `REL-001`、健康和私人事务保持本机私密，不能出现在公司、飞书或云端共享队列。
7. 任何外部写入均停在明确确认前，现有路由、导航、日历、任务和 Agent 记录不受影响。
