# ZOS v1.11 同步可靠性中心设计

## 目标

把当前“能同步”升级为“看得懂、失败能自愈、冲突可处理、误操作可恢复”。保持飞书 ERP 只读、Obsidian 正文不上云、所有写入按当前登录用户隔离。

## 产品范围

1. 数据健康页升级为统一同步中心：展示在线状态、当前设备、最近成功时间、待上传数量、失败次数、下一次重试与冲突数量。
2. 网络失败自动进入重试队列，采用递增退避；网络恢复、页面回到前台或本地数据变化时自动补同步。
3. 决策和目标发生并发修改时，提供“保留本机、使用云端、逐字段合并”三种处理方式，处理前不覆盖任一版本。
4. 提醒中心提供权限、订阅、排程三段自检；支持即时测试通知与将待办推迟 10 分钟、1 小时或次日 09:00。
5. 本地保留精简操作日志，记录新增、编辑、完成、删除、恢复和冲突处理；不记录密码、令牌或正文密钥。
6. 回收站只展示 30 天内可恢复项目；云端删除标记继续保留，防止旧设备把已删除数据重新带回。
7. 支持一键导出安全备份，包含业务状态、删除标记、同步基线和操作日志，不包含登录会话与 Supabase/飞书密钥。

## 交互原则

- 默认自动运行，用户无需逐个打开公司页面刷新。
- 状态只使用非技术语言：已同步、等待网络、正在重试、需要你处理、提醒未开启。
- 任何失败都保留本机数据；重试不会重复创建业务记录。
- 手动合并仅处理发生差异的业务字段，身份、版本、设备和更新时间由系统重新生成。
- 提醒自检只向当前登录用户的最新启用设备发送一条安全测试消息。

## 数据与安全

- `auditLog` 为本机私有元数据，不进入云端业务集合；最多保留最近 200 条。
- 同步状态与重试计时为运行时状态，不作为企业事实写入飞书或 Obsidian。
- 备份通过现有敏感字段清洗规则生成，下载前不上传到任何第三方。
- 生产函数继续强制 Supabase 用户鉴权；定时派发仍需 cron secret。

## 验收标准

- 原有测试全部通过，并新增可靠性测试覆盖离线、退避重试、三类冲突处理、提醒测试、稍后提醒、日志、30 天回收和安全备份。
- 桌面、平板、手机三种宽度同步中心不横向溢出，核心操作可点击。
- 正式地址加载无空白、无控制台致命错误；GitHub Pages、Supabase Edge Function 与定时任务状态可回读。
