# ZOS CEO OS V1.6 经营闭环设计

## 目标

把现有工作台从“多个只读页面”升级为每天自动汇总、可解释排序、人工确认执行的三公司经营闭环：玲丽教育接入，万嘉/花火/玲丽统一经营口径，今日 Top 3、催办、外部日历、每日行业情报与 AI Agent 共享同一事实边界。

## 不可突破的边界

- 飞书 ERP、合同和当前页面是实时经营事实；Obsidian 只提供长期知识和只读元数据。
- 外部情报始终是候选，不自动变成公司事实，不保存文章正文。
- AI 只生成解释、建议和草稿；飞书写回、外发消息、知识库正式入库继续要求人工确认。
- 缺少字段、凭证、日历订阅地址或模型配置时显示 `pending_configuration`，不得用示例数据填空。

## 统一公司经营契约

每家公司输出相同顶层结构：

- `finance`: `income`, `cashIn`, `outstanding`, `cost`, `grossProfit`；不可得字段为 `null`。
- `operations`: 核心业务量、活跃量、待交付/待课消等公司特有指标。
- `projects`: 进行中、逾期、今日到期、负责人缺失。
- `health`: 来源、记录数、最后成功时间、安全错误码。
- `records`: 仅用于风险、日历和决策生成的最小字段，不包含敏感正文。

玲丽源使用飞书 Base `PcHkbGRaUas8J2sn7o8cAphgntB`。表 ID 与字段必须由实时回读确认后配置为 Supabase Function Secrets；连接器授权过期期间不把历史表名当成当前事实。

## 每日行业情报

情报中心保留现有飞书候选池，并增加公开外部补采层：

1. AI/经营工具：AI HOT 最近 24 小时精选，按公开 API 契约读取。
2. 万嘉、花火、玲丽：继续读取飞书候选池中的公司标签；后续可通过允许列表增加官方 RSS/JSON 源。
3. 所有条目标准化为 `external_id/title/source/source_url/published_at/captured_at/score/relevant_companies/fact_summary/status`。
4. 以 `user_id + external_id` 幂等写入 Supabase 私有缓存，只保存摘要和来源链接。
5. 定时任务复用现有 15 分钟刷新；外部源设时间窗和数量上限，失败不影响飞书情报缓存。

首页显示当天 Top 5；情报中心按万嘉、花火、玲丽、CEO 分组。用户可标记已读、转行动或忽略。

## 今日 Top 3 与催办

确定性优先级引擎从真实任务、项目、风险、回款/交付、日历冲突和高分情报中选 3 条。每条必须包含：来源、原因、截止时间、负责人、建议动作和证据更新时间。排序规则依次为：已逾期 > 今日到期 > 高风险/回款/交付 > 日历冲突 > 高分情报。AI 只能改写说明，不能改变事实排序。

催办中心先提供站内提醒与浏览器通知适配器；飞书消息只生成预览，继续走人工确认。

## 外部日历

日历中心聚合内部任务/项目/个人占位，并增加标准 ICS 只读适配器。订阅地址只放服务端 Secret，浏览器不保存。未配置时显示明确入口；配置后缓存最小事件字段并检测冲突。Google、Apple、Outlook 可通过 ICS 统一接入，飞书日历作为后续独立适配器。

## AI Agent

四个只读建议角色共享同一契约：CEO 总控、万嘉经营、花火交付、玲丽招生/课消。输入只包含聚合事实、已授权最小记录和知识元数据；输出为 `summary/risks/actions/questions/sourceRefs`，默认进入 Inbox 待审核。模型未配置时使用确定性简报，不宣称 AI 已运行。

## 验收

1. 单元/契约：字段缺失、重复情报、过期条目、来源失败、Top 3 可解释性、ICS 隐私。
2. 集成：三公司和情报一次刷新、部分失败保留旧缓存、签出状态、四端响应式。
3. 生产：Supabase 迁移/函数/定时任务、GitHub Pages、真实登录回读、无正文/密钥泄漏、回滚路径。
