# ZOS CEO OS v1.6.2 生产验收报告

> 日期：2026-08-03  
> 范围：飞书日历自动接入、隐私最小化、空状态修正与 v1.6 经营闭环最终验收。

## 已实现

- 未配置私有 ICS 时，服务端自动尝试本人登录邮箱、已共享给 Jarvis 的日历和本人姓名兜底。
- 飞书日历请求只在 Edge Function 内使用应用凭证；浏览器、响应、日志和文档均不包含凭证、邮箱或日历 ID。
- 私人日程标题统一显示为“个人安排”，不读取或返回日程正文。
- 日历页明确区分“飞书日历已连接、当前无可见日程”和“外部日历尚未配置”。
- ICS 仍保留为 Google、Apple、Outlook 的可选服务端只读适配器。

## 三轮验收

1. **全量自动测试**：293/293 通过。
2. **静态与回归**：53 个 JavaScript 模块语法检查通过；全量自动测试再次 293/293 通过。
3. **生产回读**：`zos-calendar-data` 已部署；真实 Supabase 登录态请求返回 `state=synced`、`source=feishu`、错误为空。当前应用可见时间范围内为 0 条日程，未显示模拟数据。

## 真实性与边界

- “已连接”只证明 Jarvis 当前可见日历的读取链路正常，不代表已读取朱帅未共享给应用的私人主日历。
- 当前 0 条为真实空结果；工作台不得将其替换为示例日程。
- 如需显示本人主日历事件，只需在飞书日历中把目标日历共享给 Jarvis 应用；代码和 Supabase 无需再次修改。
- 所有日历、经营数据、情报与 Agent 输出继续保持只读或待审核；不会自动写飞书、Obsidian 或外发消息。

## 回滚

- 前端：回退到 v1.6.1 对应 Git 提交并重新发布 GitHub Pages。
- Edge Function：重新部署 v1.6.1 的 `zos-calendar-data`；不会影响经营数据缓存或用户私有记录。
- Secret：可移除 `FEISHU_OWNER_NAME`；不会触碰 `FEISHU_APP_ID/SECRET`。
