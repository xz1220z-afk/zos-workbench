# ZOS CEO OS v2.0.2 数据不丢失闭环设计

日期：2026-08-07  
状态：已获用户批准，待实施

## 目标

在不牺牲离线可用性的前提下，确保版本升级、备份导入和跨端同步过程中，用户创建的任务、日历、情报、知识卡、内容资产及 AI 工作记录不会因应用升级或错误恢复操作丢失。

## 已确认规则

- 数据继续采用本机优先、登录后自动同步 Supabase 的模式。
- 备份恢复默认采用“安全合并”，保留当前存在的记录，不自动删除任何内容。
- 所有破坏性恢复动作都必须先生成当前数据快照，并允许撤销。
- 备份中不得包含 Supabase 登录令牌、密钥或其他凭证。
- 本次变更不修改现有 Supabase 表结构，不影响未登录状态下的离线使用。

## 方案比较

### A. 本机优先 + 完整备份恢复 + 云端同步（采用）

优点：离线可用、升级风险低、与现有架构一致；用户即使暂未登录，也能创建内容并在之后同步。  
代价：需要同时维护本机快照、下载备份和云端同步三层状态。

### B. 云端优先，未同步成功不允许保存

优点：中心数据单一。  
缺点：网络或登录异常会阻断使用，不适合移动端、差网络和临时记录场景。

### C. 仅依赖数据库定时快照

优点：基础设施层恢复能力强。  
缺点：无法保护尚未上传的本机编辑，也无法解决用户误导入或版本迁移造成的本机覆盖。

## 功能设计

### 1. 统一完整备份

- 设置页旧“导出”入口与数据健康页统一使用完整备份协议。
- 备份覆盖 `state-store` 中所有集合、基础修订号、生成时间、应用版本、记录统计和完整性摘要。
- 继续兼容旧版 1.0.4 四集合备份，导入时转换成统一状态后再安全合并。

### 2. 安全合并恢复

- 先解析和验证文件，再展示来源版本、生成时间和各类记录数量。
- 按稳定 ID 合并；备份中的新增和更新记录可恢复，当前备份中没有的记录继续保留。
- 不把备份中的删除标记直接传播为云端删除。
- 恢复后的记录获得新的修订号和更新时间，使同步引擎能把它识别为本次明确恢复。
- 关键数据与云端较新版本冲突时进入现有冲突中心，不静默覆盖。

### 3. 自动安全快照与撤销

- 版本变化后在首屏渲染完成后异步生成升级前快照，不阻塞启动。
- 每次导入前自动保存当前完整状态。
- 使用 IndexedDB 保存最近 3 份快照和最近一次导入前快照，避免复制完整状态挤占 localStorage。
- 浏览器不支持 IndexedDB 或配额不足时，阻止导入并要求先下载备份，不带风险继续。
- 提供“撤销上次恢复”，通过安全合并方式恢复导入前快照。

### 4. 可见的同步与保护状态

- 数据健康页显示：本机已保护 / 云端已同步、最近成功同步时间、待同步数量、可用快照数量。
- 最近成功同步时间持久化，刷新页面后不再回到“等待首次同步”。
- 设置页提供：下载完整备份、选择备份文件、恢复预览、确认安全合并、撤销上次恢复。

## 错误处理与安全边界

- JSON 非法、格式不支持、体积异常、校验不一致或集合结构异常时拒绝导入，并保持当前数据不变。
- 导入过程中任一步失败都不替换现有状态。
- 不记录或导出登录邮箱以外的认证信息；令牌、密钥和 Supabase session 一律排除。
- 自动快照只在后台空闲阶段运行，不增加首屏阻塞。

## 验收标准

1. 新版完整备份包含所有当前集合且不含凭证。
2. 旧版备份可以安全合并，当前额外记录不会被删除。
3. 导入前自动快照可撤销，失败导入不会改变任何数据。
4. 版本升级快照最多保留 3 份，不阻塞首屏。
5. 登录状态下恢复的数据进入自动同步；未登录状态下仍可离线保存。
6. 全量自动测试通过，正式站资源版本一致。
7. 桌面、平板、手机三轮验收均满足：正文可见、无横向溢出、控制台 error 为 0。
