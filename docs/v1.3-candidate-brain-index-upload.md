# V1.3 候选：企业大脑只读索引跨端上传

## 目标

让已登录的 ZOS 用户将本机 Obsidian 扫描器产出的**只读元数据**同步到个人 Supabase 缓存，并可在其他已登录设备读取；不读取、不传输、不写入任何笔记正文。

## 已实现的本地候选

1. `scripts/obsidian-metadata-scan.mjs` 在本机扫描后生成 JSON。
2. 工作台允许用户手动选择该 JSON；浏览器先校验 `source=brain`、`mode=read_only` 和禁止正文类字段。
3. `zos-brain-index` Edge Function 再次校验用户 JWT、payload 大小、条数、元数据字段与正文禁令。
4. 端点仅通过服务器端服务角色把数据 upsert 到 `zos_business_cache(user_id, 'brain')`；RLS 继续只允许用户读取自己的缓存。

## 不包含

- 不读取或上传 Markdown 正文、附件、密钥、聊天记录或飞书数据。
- 不向 Obsidian 写入、移动、删除或自动批准任何笔记。
- 不修改飞书资源、应用权限或 ERP 数据。
- 不自动部署、推送或覆盖当前生产版本。

## 上线前验收闸门

1. 2026-08-07 Production Review 明确批准该候选进入发布。
2. 在 Supabase 控制台确认 `002_business_data_cache.sql` 与 `003_projects_cache.sql` 已实际应用，且 `zos_business_cache` 的 SELECT RLS 正常。
3. 部署 `zos-brain-index` 后，以普通登录用户测试：合法索引返回 200；未登录返回 401；含 `content` 的索引返回 400；另一用户读不到该缓存。
4. 用两台已登录设备做一次：本机扫描 → 手动选择上传 → 第二设备刷新 → 仅看到目录元数据。
5. 回滚方式：停用/回退该 Edge Function，并保留缓存表数据不做删除；旧客户端继续显示空态或旧缓存。
